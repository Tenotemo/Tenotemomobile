TENOTEMO EARN PILOT — INSTALLATION

1. Existing prerequisites: tenotemo_normal_games_migration.sql and tenotemo_spotlight_migration.sql must already be installed in the SAME Supabase project used by index.html. Existing authentication, Premium and Spotlight remain.
2. Run tenotemo_earn_migration.sql in Supabase SQL Editor. It creates separate Memory Credits, advertiser package and campaign tables, private earnings records, secure credit claims and admin-only approval functions. It revokes direct authenticated execution of legacy daily cash-prize settlement functions. Historical award rows are NOT deleted. Audit any other server-side triggers/cron jobs that may still call legacy settlement.
3. Deploy index.html, tenotemo-spotlight.js, tenotemo-versus.js, tenotemo-earn.js, and api/r.js to your Vercel project's ROOT (api/r.js stays in api/). Keep the existing project's build settings.
4. In Vercel server-side Environment Variables set SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, and TENOTEMO_REFERRAL_SALT (long random secret). Never expose service role key in client-side HTML/JS or GitHub. Redeploy after saving environment variables.
5. For advertiser setup: a company or individual service provider registers an ordinary Tenotemo account, submits a Spotlight post with approved HTTPS destination, pays agreed company package by EFT; admin verifies funds, approves post, grants package and creates campaign from Tenotemo Earn admin controls. Company exposure is added to existing purchased Spotlight views (100 views per credit). Campaign reward budgets are accounting limits; verify actual company funding separately before approving player rewards.
6. Players claim previous completed days (within 30 days) in Tenotemo Earn. A score >0 in a normal game is used as a provisional completed-challenge signal; improve server-side completion verification before large-scale use. Ranking bonus is based on the final previous-day active-player ranking. Existing normal-game scores are client-submitted and should be fraud-audited.
7. Share & Earn uses /api/r?code=... links. Vercel function redirects to approved HTTPS company link and records one indicative visit per referral/device-signature/day. It CANNOT prove a WhatsApp/Facebook Status was posted, a sale occurred, or a human saw an ad. Do not automatically award cash for clicks. Manual admin rewards must have independently verified evidence.
8. Admin-approved earnings are private to each player. Cash transfers are MANUAL, and the paid status can be set only through admin-only tenotemo_admin_reward_paid(p_reward_id) RPC after confirming EFT. Pilot UI does not automate payouts.
9. Advertiser packages: Individual R100/10 Spotlight credits (proposed R20 reward budget); Starter R500/50 Spotlight credits; Growth R1500/200; Premium R5000/750. These are proposed commercial prices, not automated subscriptions. Premium PLAYER R50/month is unchanged.
10. Run a controlled pilot and obtain appropriate SA legal, tax and privacy review before paying cash or promoting earnings claims. No guarantees of income.

INDIVIDUAL ADVERTISER UPDATE:
If the ORIGINAL Tenotemo Earn SQL is already installed in Supabase, run ONLY tenotemo_individual_advertisers_update.sql, not the full migration again. For a NEW database, run the included updated tenotemo_earn_migration.sql after prerequisites.
The advertiser application is a signed-in profile, not a purchase. The admin dashboard lists applicants and allows selecting their UUID. Approve Spotlight content and verify cleared EFT before granting the Individual R100 / 10-credit package or any larger package. Proposed R20 individual reward budget is NOT funded automatically by the package RPC: verify and record funding before setting campaign budget and approving rewards. Company and individual accounts use the same campaign and referral system.

60/40 PLAYER REWARD UPDATE + PREVIOUS-DAY LEADERBOARD (September 2026):
1. Run tenotemo_earn_6040_previous_day_update.sql in Supabase SQL Editor AFTER both existing Earn and Individual Advertisers migrations. Run it even if the previous migrations were installed earlier. This is the NEW update, not a replacement for those prerequisites.
2. Deploy ALL updated site files at GitHub repository root (api/r.js inside api/). The new daily leaderboard opens on Previous day by default; use Today to see the live ranking. Previous day displays game points, daily challenge credits, and Top 50 bonus in one credits column. Credits are credited to the wallet ONLY when the player claims that day in Tenotemo Earn, once per date within 30 days. A player's own claim status appears next to their credits.
3. Package split: Individual R100 = R60 player budget + R40 platform; Starter R500 = R300 + R200; Growth R1500 = R900 + R600; Premium R5000 = R3000 + R2000. Spotlight credits remain 10/50/200/750 respectively. Admin campaign creation is restricted server-side to remaining package reward allocation across active/paused unexpired campaigns. Existing campaigns are NOT retroactively increased. If old campaigns already exceed the new allowance, close/expire them before adding new ones; do not delete valid rewards.
4. IMPORTANT: An admin package grant is not payment escrow and does not prove funds were received. Verify cleared EFT and earmark the promised player reward budget before launching a campaign. The unused portion can be retained only after campaign completion and resolution of valid pending claims, as specified in advertiser terms. No automatic player payouts have been enabled.
5. Daily challenge completion remains provisionally inferred from recorded best_points > 0 in each normal game. Prior-day credits will not appear if normal-game score records are absent, dates are outside the 30-day window, or the update SQL has not been applied. Existing normal-game scores are client-submitted and require anti-fraud validation before high-value rewards.
